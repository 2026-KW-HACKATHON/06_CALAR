```sql
PRAGMA foreign_keys = ON;
```

> ⚠️ `PRAGMA foreign_keys`는 DB 파일에 저장되지 않고 **그 연결에만** 적용됩니다. 백엔드는 DB 연결을 열 때마다 이 문장을 실행해야 합니다. 안 그러면 `REFERENCES` 검사와 `ON DELETE CASCADE / SET NULL`이 오류 없이 무시됩니다.

> 🕒 `datetime('now')` 기본값은 **UTC**라서 한국 시간과 9시간 차이가 납니다. 그래서 구현에서는 주문을 만들 때 서버가 한국 시간(KST) 문자열을 `created_at`에 직접 넣고, 기본값에 기대지 않습니다. `pickup_time`도 KST 기준 `YYYY-MM-DDTHH:mm`이라 두 값을 그대로 비교할 수 있습니다.

CREATE TABLE IF NOT EXISTS categories (

	parent_id INTEGER DEFAULT NULL REFERENCES categories(category_id) ON DELETE CASCADE

```sql
CREATE TABLE IF NOT EXISTS stores (
	store_id INTEGER PRIMARY KEY AUTOINCREMENT,
	owner_id INTEGER,
	name TEXT,
	category_id INTEGER REFERENCES categories(category_id) ON DELETE SET NULL,
	description TEXT,
	phone TEXT,
	address TEXT,
	location_lat REAL,
	location_lng REAL,
	open_hours TEXT,
	order_type TEXT DEFAULT 'none' CHECK (order_type IN ('preorder', 'reservation', 'none')),
	visits INTEGER DEFAULT 0,
	created_at DATETIME DEFAULT (datetime('now')) NOT NULL
);
```

이거는 가게 노드 <br>
`owner_id`는 이 가게 점주의 계정 id (로그인 계정 테이블의 `user_id`). 점주용 API는 로그인한 사용자의 id가 이 값과 같은지 확인함 <br>

```sql
CREATE TABLE IF NOT EXISTS coupons (
    coupon_id INTEGER PRIMARY KEY AUTOINCREMENT,

    store_id INTEGER NOT NULL
        REFERENCES stores(store_id)
        ON DELETE CASCADE,

    title TEXT NOT NULL,
    description TEXT,

    discount_rate REAL NOT NULL
        CHECK (discount_rate BETWEEN 0 AND 100),

    valid_from DATETIME,
    valid_until DATETIME,

    is_active INTEGER NOT NULL DEFAULT 1
        CHECK (is_active IN (0, 1)),

    created_at DATETIME NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE IF NOT EXISTS signKeyWords (
	id INTEGER PRIMARY KEY AUTOINCREMENT,
	name TEXT NOT NULL,
	store_id INTEGER NOT NULL REFERENCES stores(store_id) ON DELETE CASCADE,
	UNIQUE (store_id, name)
);

CREATE TABLE IF NOT EXISTS menus (
	menu_id INTEGER PRIMARY KEY AUTOINCREMENT,
	name TEXT NOT NULL,
	store_id INTEGER NOT NULL REFERENCES stores(store_id) ON DELETE CASCADE,
	price INTEGER NOT NULL,
	rating REAL CHECK (0 <= rating AND rating <= 5)
);

CREATE TABLE IF NOT EXISTS orders (
	order_id INTEGER PRIMARY KEY AUTOINCREMENT,
	store_id INTEGER NOT NULL REFERENCES stores(store_id),
	customer_id INTEGER,
	total_price INTEGER,
	pickup_time TEXT NOT NULL,
	customer_phone TEXT NOT NULL,
	status TEXT NOT NULL DEFAULT 'pending' CHECK (status IN ('pending', 'accepted', 'done', 'rejected')),
	created_at TEXT DEFAULT (datetime('now')),
	is_active INTEGER DEFAULT 1
);

CREATE TABLE IF NOT EXISTS items (
	item_id INTEGER PRIMARY KEY AUTOINCREMENT,
	order_id INTEGER NOT NULL REFERENCES orders(order_id) ON DELETE CASCADE,
	menu_id INTEGER NOT NULL REFERENCES menus(menu_id),
	quantity INTEGER DEFAULT 1 CHECK (quantity > 0),
	unit_price INTEGER NOT NULL CHECK (unit_price >= 0)
);
```

- `signKeyWords`는 `UNIQUE (store_id, name)`이 이미 `store_id`로 시작하는 인덱스를 만들어 주므로 `store_id` 인덱스를 따로 만들지 않음
- 가게·메뉴는 실제로 지우지 않고 삭제 표시만 함 (구현에서는 `deleted_at` 컬럼, 소프트 삭제). 그래서 `orders.store_id`, `items.menu_id`가 `ON DELETE` 없이 걸려 있어도 주문 기록이 있는 가게·메뉴 삭제가 막히지 않음
- `items.unit_price`는 주문 당시 메뉴 1개 가격. 메뉴 가격이 나중에 바뀌어도 주문 금액은 그대로 남음
- `stores.owner_id`, `orders.customer_id`는 로그인 계정 id (구현의 `account_ids.user_id`, 계정이 지워지면 `NULL`). 계정 테이블은 `backend/setup.sql` 참고
- 변경 이력 테이블(`importantDetailsUpdate`)은 구현에서 제거됨 (`backend/db.js`가 기존 DB에서도 삭제함)
- 이 문서는 핵심 테이블만 정리한 것. 실제 전체 스키마(계정·결제·사진 등)는 `backend/setup.sql`이 기준
