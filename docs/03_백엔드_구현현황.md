# 백엔드 구현 현황 및 미협의 결정사항

> 작성: 2026-09-30 · 브랜치 `feature/backend-setup`
> 기준 문서: `docs/api-spec` 브랜치의 `docs/02_API_명세.md`

API 명세의 엔드포인트 8개를 모두 구현했고, 자동 테스트 38개로 검증했습니다.
단, **명세에 없어서 팀 협의 없이 임시로 정한 부분**이 있습니다. 아래 [3. 협의 없이 임시로 정한 것](#3-협의-없이-임시로-정한-것-)을 꼭 확인하고, 다르게 가고 싶은 부분이 있으면 말씀해 주세요. 대부분 숫자나 규칙 한 줄만 바꾸면 되도록 만들어 두었습니다.

---

## 1. 실행 방법

**Node.js 22 이상**이 필요합니다.

```bash
cd backend
npm install
npm start          # http://localhost:3000
npm test           # 자동 테스트 38개 (약 10초)
```

- 포트 변경: `PORT=4000 npm start`
  - 포트가 이미 사용 중이면 안내 메시지를 출력하고 종료합니다.
- 서버를 켜면 간판 인식(OCR)을 미리 준비합니다. `간판 인식(OCR) 준비 완료` 로그가 나오면 준비된 것입니다.
- OCR 언어 데이터(한국어·영어)는 `npm install` 때 npm 패키지(`@tesseract.js-data/*`)로 설치됩니다. **서버 실행 중에는 인터넷이 필요 없습니다.**
- 데이터는 **메모리에만** 저장됩니다. 서버를 재시작하면 새로 만든 주문은 사라지고 샘플 데이터 상태로 돌아갑니다.

## 2. 구현 현황

| 기능 | 메서드 | 주소 | 상태 |
|---|---|---|---|
| 가게 목록 조회 | `GET` | `/api/stores` | ✅ 명세대로 (+ 입력 검증, 3-7) |
| 가게 상세 조회 | `GET` | `/api/stores/:id` | ✅ 명세대로 (+ 방문수 집계, 3-5) |
| 간판 인식 | `POST` | `/api/stores/recognize` | ✅ 동작함 (임시 OCR, 3-1) |
| 동네 추천 목록 | `GET` | `/api/stores/recommendations` | ✅ 동작함 (추천 기준 임시, 3-2) |
| 주문/예약 생성 | `POST` | `/api/orders` | ✅ 명세대로 (+ 추가 검증, 3-3) |
| 주문 상태 조회 | `GET` | `/api/orders/:id` | ✅ 명세대로 |
| 가게별 주문 목록 | `GET` | `/api/stores/:id/orders` | ✅ 명세대로 (정렬 기준, 3-4) |
| 주문 상태 변경 | `PATCH` | `/api/orders/:id/status` | ✅ 명세대로 (상태 규칙, 3-4) |

공통 사항은 다음과 같습니다.
- 모든 에러는 명세대로 `{ "error": "메시지" }` 형태입니다.
- 프론트 개발 서버(Vite 등)에서 바로 호출할 수 있게 **CORS를 전부 허용**해 두었습니다.
- 명세에 없는 주소로 요청하면 `404 { "error": "Not found" }`가 옵니다.

## 3. 협의 없이 임시로 정한 것 ⚠️

### 3-1. 간판 인식 방식

README에는 간판 인식을 `image-proc/`(C / Rust)에서 하기로 되어 있지만, 아직 비어 있습니다. 그래서 **백엔드에서 임시로 동작하게** 만들었습니다.

**흐름**
1. 사진을 업로드합니다.
2. 파일 내용으로 진짜 이미지인지, 해상도가 얼마인지 검사합니다.
3. OCR(`tesseract.js`, 한국어+영어)로 글자를 읽습니다. 이진화 방식 2가지로 읽고 결과를 합칩니다.
4. 읽은 글자를 가게 이름·`signKeywords`와 비교해서 매칭된 가게를 돌려줍니다.

**매칭 규칙**
- **가게 이름 전체가 보이거나, 키워드가 2개 이상 보여야** 그 가게로 인정합니다.
  - 그래서 "월계부동산", "스타벅스 카페", "엄마손칼국수" 같은 다른 가게 간판은 매칭되지 않습니다.
- 다른 키워드에 포함되는 키워드('손칼국수' 안의 '칼국수')는 따로 점수를 주지 않습니다.
- 띄어쓰기, 특수문자(`·`, `!`), 줄바꿈은 무시하고 비교합니다.
- 결과는 점수가 높은 순서입니다. 첫 번째가 가장 유력한 후보입니다.

**인식 정확도 (테스트 결과)**
- 테스트용으로 만든 간판 이미지 9장에서 모두 맞았습니다.
  - 가게 간판 6장(png/jpg/webp, 기울어진 간판, 노란 바탕 포함)은 전부 올바른 가게로 인식했습니다.
  - 다른 가게 간판 3장은 모두 매칭되지 않았습니다.
- ⚠️ 이 이미지들은 컴퓨터로 만든 깨끗한 간판입니다. **실제 휴대폰 사진(원근, 조명, 흔들림)으로는 아직 테스트하지 못했습니다.** 데모 전에 실제 사진으로 확인이 필요합니다.

**업로드 제한** (명세에 숫자가 없어서 임의로 정함)

| 상황 | 응답 |
|---|---|
| 이미지 파일 누락 | `400 Image file is required` |
| jpeg/png/webp가 아님 (**파일 내용으로 판단**. 이름·형식을 속여도 걸러짐, 아이폰 HEIC도 여기 해당) | `400 Unsupported file type` |
| 헤더는 정상인데 내용이 깨진 이미지 | `400 Invalid image file` |
| `image` 필드가 아니거나 파일 2개 이상 | `400 Send exactly one image file in the 'image' field` |
| 10MB 초과 | `413 File too large` |
| 해상도 5천만 화소 초과 (파일은 작아도 메모리를 폭발시키는 이미지 방지) | `413 Image dimensions too large` |
| 인식 요청이 한꺼번에 5개 넘게 몰림 | `503 Sign recognition is busy, please try again` |
| OCR 준비 실패 | `503 Sign recognition is temporarily unavailable` |
| 인식이 30초 넘게 걸림 | `504 Sign recognition timed out` |
| 인식 중 OCR 프로세스 비정상 종료 | `500 Sign recognition failed` |

→ **프론트는 200이 아닌 응답이 오면 전부 "수동 검색으로 전환" 안내를 보여주면 됩니다.**

**안정성**
- OCR은 별도 프로세스에서 돌립니다. tesseract.js에는 깨진 이미지 하나로 서버 전체가 죽거나 언어 데이터 로딩 실패 시 영원히 멈추는 문제가 있는데, 별도 프로세스라서 메인 서버는 영향을 받지 않습니다.
- 문제가 생긴 OCR 프로세스는 강제 종료하고 다음 요청 때 새로 띄웁니다.

**image-proc 연동 시**
- `backend/services/signRecognizer.js`의 `extractText(imageBuffer)`만 바꾸면 됩니다.
- "사진 Buffer를 받아 글자(string)를 돌려준다"는 약속만 지키면 라우트, 업로드 검증, 매칭 로직은 그대로 둬도 됩니다.

**🧪 명세에 없는 추가 필드: `text`**
- multipart에 `text` 필드를 같이 보내면 OCR을 건너뛰고 그 글자로 매칭합니다.
- 카메라나 OCR 없이 프론트 화면을 테스트하려고 만든 **개발용 기능**입니다. 필요 없으면 지워도 됩니다.
```bash
curl -F "image=@사진.png" -F "text=월계 손칼국수" localhost:3000/api/stores/recognize
```

### 3-2. 오늘의 동네 추천 기준

명세에는 "신규 가게 또는 저활성 가게 위주"라고만 되어 있어서 숫자를 임의로 정했습니다. 숫자는 `services/storeService.js` 위쪽 상수에서 바꿀 수 있습니다.

| 항목 | 임시값 | 상수 이름 |
|---|---|---|
| 신규 가게 기준 | 등록(`createdAt`) **30일 이내** | `NEW_STORE_DAYS` |
| 저활성 가게 기준 | 방문수(`visits`) **30 이하** | `LOW_VISITS` |
| 좌표를 보냈을 때 반경 | **2km 이내** 가게만 | `RECOMMEND_RADIUS_KM` |
| 최대 개수 | **10개** | `RECOMMEND_LIMIT` |

- 순서: **신규 가게(최근 등록순) → 저활성 가게(방문 적은 순)**
- 두 기준 모두 해당하지 않는 가게(방문 많은 오래된 가게)는 추천에 나오지 않습니다.
- 반경 안에 가게가 없으면 빈 배열 `[]`이 옵니다.

### 3-3. 주문 생성 시 추가 검증

명세의 에러 표에 없는 경우도 막아 두었습니다. 모두 `400`입니다.

| 상황 | 에러 메시지 |
|---|---|
| body가 JSON 객체가 아님 (배열, 빈 body, form 형식 등) | `Request body must be a JSON object` |
| `storeId`가 1 이상의 정수가 아님 (`"1"` 같은 문자열 포함) | `Invalid storeId` |
| `items`가 배열이 아니거나 비어 있음 | `items must be a non-empty array` |
| `items` 안의 항목이 객체가 아님 | `Each item must be an object with menuId and quantity` |
| `quantity`가 1 이상 정수가 아님 | `Invalid quantity for menuId: 101` |
| 메뉴 하나의 수량이 99 초과 | `Quantity for menuId: 101 exceeds 99` |
| `pickupTime` 형식이 틀리거나 없는 날짜 (2월 30일, 24:00 등) | `Invalid pickupTime format (YYYY-MM-DDTHH:mm)` |
| `pickupTime`이 과거 (지금 이 분까지는 허용) | `pickupTime must not be in the past` |
| `pickupTime`이 30일보다 뒤 | `pickupTime must be within 30 days` |
| `pickupTime`이 가게 영업시간 밖 | `pickupTime is outside business hours` |
| 전화번호 형식이 아님 | `Invalid customerPhone format` |

- 허용하는 전화번호: `010-1234-5678`, `01012345678`, `02-123-4567`, `031-123-4567` 등. 국제번호(`+82`)와 띄어쓰기는 불가합니다.
- **같은 메뉴가 여러 번 오면 하나로 합칩니다.** 예: 101번 2개 + 101번 1개 → 101번 3개
- 요청에 `totalPrice`, `status`, `id`를 넣어도 무시하고 서버가 정합니다 (명세대로).
- `orderType`이 `reservation`인 가게도 주문(`items` 포함)을 받습니다. 명세에서 막는 것은 `none`뿐이라서 이렇게 두었습니다.
- 시간은 모두 **한국 시간(KST)** 기준입니다. `createdAt`은 `YYYY-MM-DDTHH:mm` 형식입니다.
- JSON body가 100KB를 넘으면 `413 Request body too large`가 옵니다.

### 3-4. 주문 상태 변경 규칙

명세의 흐름도(`pending → accepted → done`, `pending → rejected`)를 그대로 규칙으로 만들었습니다.

| 현재 상태 | 바꿀 수 있는 상태 |
|---|---|
| `pending` | `accepted`, `rejected` |
| `accepted` | `done` |
| `rejected`, `done` | 없음 (`409 Order status cannot be changed anymore`) |

명세에 없던 경우는 이렇게 처리합니다.
- `pending → done`(수락 건너뛰기), `accepted → rejected`(수락 후 거절), 같은 상태로 다시 변경 → `409 Cannot change status from pending to done` 형식
  - 수락 후 취소가 필요하면 규칙 한 줄(`ALLOWED_TRANSITIONS`)만 바꾸면 됩니다.
- `status`를 안 보내면 `400 status is required`, 이상한 값이면 `400 Invalid status value`가 옵니다.
- 가게별 주문 목록은 **픽업 시간이 빠른 순**, 같으면 먼저 들어온 순으로 정렬합니다.

### 3-5. 방문수(`visits`) 집계

`visits`를 늘리는 방법이 명세에 없어서, **가게 상세 조회(`GET /api/stores/:id`) 때 방문 1회로 셉니다.**
- 같은 사용자(IP + 브라우저 정보)가 같은 가게를 **30분 안에 다시 조회하면 세지 않습니다.** 새로고침이나 React StrictMode의 중복 호출로 숫자가 부풀지 않게 하려는 것입니다.
- 한계: 같은 와이파이에서 같은 기종·브라우저를 쓰는 사람들은 한 명으로 셀 수 있습니다.
- "주문 완료 시 +1" 같은 다른 기준이 좋으면 말씀해 주세요.

### 3-6. 샘플 데이터

- 가게 5개와 주문 3개는 **가상의 데이터**입니다. 주소와 전화번호는 가짜 값이고, 좌표는 월계1동 부근입니다.
- 5번 `모퉁이 카페`는 `orderType: 'none'`입니다. "주문 안 받는 가게" 화면을 테스트할 때 쓰세요.
  - 명세 예시의 "신규 오픈 카페"는 흔한 단어로만 된 이름이라 간판 오탐 때문에 이름을 바꿨습니다.
- **`signKeywords` 작성 규칙**: 간판에 실제로 쓰인 단어를 넣되, '월계'(동네 이름), '카페'(업종)처럼 흔한 단어는 최대 1개만 넣습니다. 흔한 단어가 2개 들어가면 다른 가게 간판에도 매칭됩니다. (`data/stores.js` 맨 위 주석 참고)
- 3번 햇살 미용실 쿠폰은 금액 할인이라 `discountRate: null`입니다. 명세상 `discountRate`는 숫자인데 금액 할인 쿠폰을 어떻게 표현할지 **협의가 필요합니다** (예: `discountAmount` 필드 추가).

### 3-7. 공통 입력 규칙

| 입력 | 규칙 |
|---|---|
| 주소의 `:id` | 1 이상의 정수만. `abc`, `1.0`, `0x1`, `01`은 **없는 대상(404)**으로 처리 |
| `lat`, `lng` | 둘 다 보내야 함. 숫자(소수점 허용)이고 위도 ±90, 경도 ±180 안. 아니면 400 |
| 쿼리 값 (`category`, `keyword`, `status`) | 앞뒤 공백 무시. 비어 있으면 안 보낸 것으로 처리. 같은 키를 두 번 보내면 400 |
| `keyword` 검색 | 띄어쓰기·특수문자 무시 (`손 칼국수` → `월계 손칼국수` 검색됨) |
| `%` 인코딩이 깨진 주소 | 400 |

## 5. 프론트에서 호출할 때 참고

```javascript
const BASE = 'http://localhost:3000/api';

// 추천 목록
await fetch(`${BASE}/stores/recommendations?lat=37.62&lng=127.06`).then(r => r.json());

// 간판 인식 (Content-Type은 직접 넣지 말 것 — 브라우저가 boundary까지 알아서 붙임)
const form = new FormData();
form.append('image', file);            // <input type="file" accept="image/*" capture> 또는 카메라 캡처 Blob
// form.append('text', '월계 손칼국수');  // 개발용: OCR 없이 매칭 테스트
const res = await fetch(`${BASE}/stores/recognize`, { method: 'POST', body: form });
if (!res.ok) {
  // 400/413/5xx 전부 → "수동 검색으로 전환하시겠어요?" 안내
}
const { matched, stores } = await res.json();  // matched가 false여도 수동 검색 안내

// 점주: 주문 수락
await fetch(`${BASE}/orders/1/status`, {
  method: 'PATCH',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ status: 'accepted' }),
}).then(r => r.json());
```

- 에러가 났는지는 `res.ok`(또는 `res.status`)로 확인하고, 메시지는 `(await res.json()).error`로 읽으면 됩니다.
- `storeId`, `menuId`, `quantity`는 **숫자**로 보내야 합니다. `useParams()`로 받은 id는 문자열이니 `Number(id)`로 바꿔서 보내세요.

## 6. 자동 테스트

`npm test`로 38개 테스트를 실행합니다. 시간에 따라 결과가 달라지는 부분(영업중 여부, 과거 시간 등)은 테스트 안에서 현재 시각을 고정하므로 언제 돌려도 같은 결과가 나옵니다.

| 파일 | 내용 |
|---|---|
| `test/utils.test.js` | 이미지 헤더 분석, id·좌표·날짜 검사, 영업시간 계산, 간판 매칭 규칙 |
| `test/stores.test.js` | 가게 목록·상세·추천, 방문수 중복 제거, 404/400, CORS |
| `test/orders.test.js` | 주문 생성의 모든 검증, 조회, 가게별 목록, 상태 전이 |
| `test/recognize.test.js` | 업로드 검증, **실제 OCR로 간판 이미지 9장 인식**, 깨진 이미지, OCR 프로세스 비정상 종료, 동시 요청 제한 |

| `test/server.test.js` | `npm start` 실행, 포트 충돌 안내 |
